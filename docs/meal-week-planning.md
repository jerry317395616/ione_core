# 周食谱编排与采购使用说明

本业务通过周食谱组织 ERPNext 的物料、BOM、生产计划和采购申请。菜品配方以一名幼儿的食材用量为基准，人数来自教育管理；计划人数不代表实际出勤或实际就餐。

## 编排一周

1. 新建“周食谱编排”，选择园所公司、原料仓库、星期一、学年学期和参考食谱周，先保存空周。
2. 点击“从上一周编排”。参考周须有完整的五天、每天五餐；系统复制菜品和配方，为新周生成独立的餐次生产计划。
3. 核对早餐、早点、午餐、午点、晚餐。系统按每天的有效教育名册计算基线；未登记停餐调整时，各餐采用当天基线。它是预计供餐人数，不表示当天全员实到。
4. 有停餐时，填写“停餐调整人数”和原因后保存。人数必须为非负整数，小于当天在册人数；系统按“在册基线－停餐调整”计算本餐人数，并同步菜品生产数量。
5. 草稿阶段可点击“刷新教育人数”。刷新保留已填停餐调整；若调整超过新基线，会要求先处理。调整人数或菜品后须重新核对采购需求。

“调整本餐菜品”用于替换该餐的完整菜品配方列表。选择已提交、启用、属于本园所、以一名幼儿为基准的自制菜品 BOM；保存后重新查看采购预览。受管生产计划的日期、人数、配方和采购来源应通过周计划维护。

## 看带量、备料和采购需求

- “周食谱表”显示每天每餐菜品及**人均带量**，可导出、打印。
- “食材需求明细”显示人均带量、计划人数和**备料总量**；总量为人均用量乘本餐人数。
- “采购需求预览”进一步核对库存、按需求日期可用的到货、已申请量、采购单位和本次申请量。同一库存按整周顺序分配一次。

采购方式在食材物料上明确维护。厨房用水不生成采购申请；成品采购与厨房自产配料应分别配置，自产配料未补齐配方时会阻止采购。采购单位仅使用已确认的换算关系。没有有效参考价格可先核定申请数量，之后询价。

库管、采购负责人或系统管理员点击“核对账面库存”。**草稿阶段可以重复复核**，每次保存当前需求依据；该记录不表示完成实物盘点。人数、菜品、库存、到货或采购设置变化后，重新预览并复核，不能沿用旧确认。

## 审核、申请和后续采购

食谱审核员或系统管理员提交周计划。系统重新检查教育名册、配方和已复核的采购依据；一致后统一提交餐次生产计划并冻结本周依据。

授权采购负责人从周计划点击“生成采购申请草稿”。生成的是原生 **Material Request，类型为 Purchase**，每行保留餐次生产计划及原料来源。重复点击返回同一张关联申请。该操作不会自动下单、收货或付款。

采购人员核对申请并按园所规则提交，随后采用原生流程：

**采购申请 → 询价／报价比较（需要时）→ 采购订单 → 采购收货单 → 采购发票 → 付款。**

继续操作时从原单据创建后续单据，保留来源关联。按实际到货验收，不把采购申请数量当作已入库数量。参见 [ERPNext 官方采购流程](https://docs.frappe.io/erpnext/procurement-cycle-overview)。

## 复制下一周与修订

已审核周可点击“复制到下一周”，选择目标星期一。新周复制菜单并重新读取教育人数，形成草稿；同一园所同一周只能有一个有效计划。

已审核后需要更改人数或菜单，应由有权限的人员先处理关联采购申请及其后续订单，再取消周计划并使用标准“修订”。修订版本清空旧餐次、人数及采购快照，以取消版本作为菜品来源；保存后重新初始化、核对、审核。不得直接修改已提交的餐次生产计划。

**本阶段限制：**上周仍有未核销的库存承诺时，另一周的采购核算会被阻止，避免重复使用同一库存。下一周仍可复制和编排菜单，但不能据此宣称连续周采购已经全部跑通。需要维护人员核对厨房耗用和原生库存业务后处理；不能通过清空快照、强改状态或取消真实业务来绕过。

## 部署与维护

1. 先备份数据库及自定义应用，再部署扩展。元数据安装须由系统管理员**手动调用** `ione_core.meal_planning_setup.install_meal_planning`；导入模块不会安装字段，普通迁移也不能代替这一步。
2. 在教育管理维护 `Student.custom_student_batch`，关联现行 `Student Batch Name`。班级必须明确公司并启用；学生启用、校友及入退园日期需要准确。旧班级数据迁移先干跑核对，再由系统管理员明确执行写入；正常人数查询只使用现行字段。详见 `docs/meal-population.md`。
3. 按职责配置“食谱编排员”“食谱审核员”、`Stock Manager`、`Purchase Manager`。生成采购申请还需原生申请创建权限及所关联生产计划的写权限；只读查看者不应获得这些操作权限。
4. 共享只读访问时，限定到**确切周计划及其关联生产计划**。在初始化前共享周，或共享后调用内部 `share_linked_plans`；已有生产计划 User Permission 范围时，仅追加新周的关联编号。另行配置两个脚本报表的允许角色，周共享本身不能替代报表角色权限。
5. 用实际业务角色检查周页面、关联生产计划、两个报表及越权操作；确认其他周和其他生产计划的访问范围符合要求。保持 Frappe／ERPNext 官方源码不变，使用扩展中的控制器、字段和 hooks。

实现入口：`ione_core/meal_planning.py`、`ione_core/meal_population.py`、`ione_core/meal_procurement.py`。元数据、角色和表结构修改可能跨越数据库事务边界；业务生成与验收应由调用方明确提交或回滚。
