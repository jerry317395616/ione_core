# 跨周食材实物认领

`meal_stock_claims.py` 只重放冻结数量及 ERPNext 原生实物流水，不写 Bin、不替换官方库存占用算法、不提交事务。采购、领用和退货都不能挪走其他周已经认领的食材。

## 原料仓计算

每个物料、实际仓库、周分别计算：

`剩余原料归属 = 冻结新增现货认领 + 原生净采购到货 + 额外领用前新增认领 - 净领入厨房量`

- v1 以原冻结 `allocated_stock_qty` 作开仓认领；v2 只累计 `new_physical_claim_qty`。变更复用已有 own 池不再新增认领，避免原80克被替换菜品再次认领成160克。
- 到货必须核实 PR→PO→MR→PP→Week，逐行匹配物料及仓库，并由非取消 SLE 证明真实库存量。退货按负 SLE 减少原归属周的实物。
- 厨房领用／退料必须通过原生 Stock Entry 及 SLE／厨房历史来源链验真。退料增加当前执行周在真实原领用源仓的份额，不复活已核销旧周。
- 额外实际领用可使用尚未归属的真实余量。正式领用提交时冻结 `custom_meal_raw_claim_snapshot`，绑定周、SE、源仓、逐物料 own/free 数量及哈希；草稿不认领库存。
- 未到货 MR／PO 是本周采购防重承诺，不是实物。厨房余量属于实际厨房位置及来源链，不变成原料仓的虚拟可用量。

原生 Bin 的销售、生产、分包及非食谱 PP 占用继续保留。已验证食谱 PP 的 raw 与 in-house subassembly 毛需求贡献被精确排除，再用上述实物归属替代。存在关联工单、额外库存预留、冻结依据损坏、缺 SLE、负归属或总归属超过账面可用量时，停止自动分配，不能静默截成零。

## 提前模式

同原料仓有此前未核销周，且当前日期早于新周开始日期时，free 池不用于新周采购抵扣。例：A有80现货、另申请20；B需要100。B提前申请100。B先到100后，180实物中A仍只有80、B有100；A自己的20到货后，双方各有100。A领走自己的100后，原料仓剩下的100仍属于B。

这是一项保守策略，可能多备货。原申请、订单、收货不因后来产生余料而自动改写；买方应核对实际未执行数量，再走原生减少／关闭／退货流程。

## 守卫与锁

所有变更入口先 `lock_claim_scope(company)`，再依次锁周、原生来源及 Bin。写路径使用 current read；只读预览用一致性读取。数据库事务过旧而与原生 PP 占用输入不一致时仍按既有保护拒绝并要求刷新，绝不切换全站隔离级别或中途提交。

- `build_claim_context(week, codes, warehouses, for_update=False, exclude_entry=None)`：内部 own／other 归属、managed PP 毛占用、advance 模式及证据。
- `physical_pools(claims, bins)`：返回互不重叠的 own／free 池与公开汇总。
- `assert_week_raw_stock_available(week, quantities, exclude_entry=None)`：正式领用前验证份额并返回 SE 归属证明。
- `before_submit_purchase_receipt`／`before_cancel_purchase_receipt`：投影退货、收货取消及反取消退货的物理变化；无映射普通 PR 的减少也必须保留其他周份额，内部收货还按原生来源量投影调出仓及拒收仓的库存腿。已耗用的本周到货不能借其他周补退。
- `validate_purchase_receipt` 接入提交后更新：冻结已提交膳食 PR 的库存／采购来源及影响账簿的 header，保留原生账单状态维护。

正式 PR 取消还独立比对数据库原始 header 与明细，不能先篡改日期、退货标记、公司、币种、拒收数量／仓库、调出仓及序列／批次来源等再借取消路径绕过验证。当前本周专属收货不自动处理混合拒收、内部调拨或委外，完整厨房链暂不支持批次／序列食材；原生库存盘点造成份额不符时必须人工核实真实原因，不伪造认领修订。

正式站不通过演练生成库存。A80／B100、交错到货、领用、退货、取消与变更复用，应同时有离线数量测试和隔离库原生 PR／SE／SLE 集成证据。
